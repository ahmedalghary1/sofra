# Serveza — SaaS لإدارة المطاعم

تطبيق Django عربي RTL لإدارة المنيو والطاولات وطلبات الضيوف والمطبخ والخدمة. بدأ من مواصفات [المنتج الأصلية](safra_restaurant_saas_complete_spec.md) في هذا المجلد. الواجهة تتكيف مع الهاتف والتابلت وسطح المكتب.

الهوية الحالية هي Serveza، وفق [دليل التطبيق](docs/BRAND_IDENTITY.md). ملف المواصفات الأصلي يحتفظ باسم العمل السابق كمرجع تاريخي.

## ما يعمل الآن

- إنشاء حساب مالك ومطعم، مع تأكيد البريد ثم طلب التواصل لاختيار الباقة وتفعيل الاشتراك يدويًا من مسؤول المنصة، وتسجيل دخول الموظفين بأدوار واستعادة كلمة المرور عبر البريد.
- إدارة الفروع واختيار الفرع الحالي، ودعوة الموظف بالبريد مع دور وفرع وقبول لمرة واحدة، وتعطيل عضويته أو تغيير دوره.
- تعديل اسم المطعم ووصفه وبيانات اتصال الفرع وساعات العمل، مع خيار لنشر بيانات الفرع في منيو الضيف.
- إدارة التصنيفات والأصناف والأسعار والصور والتوفر والأحجام والإضافات، واستيراد منيو CSV وXLSX بمعاينة قبل الاعتماد، والطاولات مع تنزيل QR وتجديد الرمز.
- منيو ضيف عام بلا تسجيل، سلة مع كمية وإضافات، إرسال طلب مع إعادة احتساب الأسعار في الخادم ومفتاح منع التكرار.
- شاشة مطبخ تفحص البيانات كل 10 ثوانٍ وتوضح حالة الاتصال، انتقالات حالات مسجلة، واستدعاء الويتر أو الحساب.
- طلب تقليدي متعدد الأصناف والإضافات من الموظف، وتعديل الطلب الجديد أو المستلم وغير المدفوع مع سجل قبل/بعد، وإلغاء بسبب مسجل، وتحصيل يدوي منفصل عن حالة الطلب، وتقارير بفترة زمنية وتصدير CSV، ولوحة مشغل لإدارة المطاعم والاشتراكات مع سبب وسجل تدقيق.

**الحالة:** إصدار تجريبي تشغيلي، وليس جاهزًا للإطلاق التجاري. تفاصيل المؤجل والمخاطر في [خطة التنفيذ](docs/IMPLEMENTATION_PLAN.md).

## التشغيل المحلي

يتطلب Python 3.12+.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```

افتح `http://127.0.0.1:8000/` لإنشاء حساب مطعم. لإنشاء أول مسؤول منصة، شغّل `python manage.py createsuperuser`. سجّل الدخول من `/login/` باسم المستخدم نفسه أو ببريده المميز وكلمة مروره. يفتح الموقع `/platform/` مباشرة لإدارة المطاعم والفروع والباقات والحسابات ومتابعة الطلبات والتحصيل والسجل.

للتطوير عبر PostgreSQL: `docker compose up --build` ثم `docker compose exec web python manage.py migrate`. إعدادات التطوير داخل Compose فقط.

## البيئة

يقرأ المشروع ملف `.env` من المجلد الرئيسي عند بدء التشغيل. عند إعداد نسخة جديدة، انسخ `.env.example` إلى `.env`. تأخذ متغيرات الاستضافة الأولوية على الملف. استخدم `DATABASE_URL` مع PostgreSQL، أو اضبط `DJANGO_ALLOW_SQLITE=1` واترك `DATABASE_URL` فارغًا لتشغيل قاعدة `db.sqlite3` مع `DJANGO_DEBUG=0` في تجربة محدودة. [إعدادات النشر والتجربة](docs/DEPLOYMENT.md)

### بريد التفعيل عبر Gmail

في ملف `.env` أدخل عنوان Gmail المرسل في `DJANGO_EMAIL_HOST_USER`، وكلمة مرور التطبيق في `DJANGO_EMAIL_HOST_PASSWORD`. عند مشاركة الموقع، ضع عنوانه العام مثل `https://your-domain.example` في `DJANGO_PUBLIC_BASE_URL` حتى يفتح رابط التفعيل على جهاز المستلم. أعد تشغيل Django بعد تعديل الملف.

الإعداد المرفق يستخدم `smtp.gmail.com` على المنفذ 587 مع STARTTLS. يحصل المالك بعد التسجيل على رسالة بلغته تتضمن رابط تفعيل صالحًا لمدة 24 ساعة. يمكنه طلب رابط جديد من شاشة التحقق. لتجربة القالب محليًا عبر سجل الخادم، اضبط `DJANGO_EMAIL_BACKEND=console`. [إنشاء كلمة مرور تطبيق Google](https://support.google.com/mail/answer/185833?hl=ar)
