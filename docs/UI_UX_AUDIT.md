# Serveza UI and UX audit

## Baseline
The existing checkout serves Django templates, Cairo from local static files, and plain browser JavaScript. The Django URL configuration is the navigation inventory. The homepage redirects authenticated members to the workspace. The public demo menu verifies totals server-side without accessing restaurant tables. Menu, kitchen, floor, billing and platform operations already have separate server-side authorization and data paths.

Before changing templates we migrated a disposable SQLite fixture, seeded the existing local demo, started Django on loopback and captured eight screens at 390, 768 and 1440 CSS pixels. Screens included the homepage, demo menu, login, guest table, owner dashboard, kitchen, service queue and platform. All 24 loads returned 200 with no page overflow, browser exceptions or asset errors in this sample. Original captures are in [redesign-evidence/before](redesign-evidence/before). This sample does not cover every state or authenticated action.

## Findings
The public homepage had two internal section links, a sculptural QR image and three benefit cards. There was no searchable catalog, pricing comparison, connected role demo, operator guide or English navigation. The guest drawer, polling kitchen and workspace already showed real operational state. The sidebar, layouts, permissions and order forms are valuable integration points. The brand book supplies 24 pages, Cairo, the navy/teal palette, an approved lockup and proposed pricing. Brand examples of uplift, contact details and commercial terms require corroboration before publication.

## Design references
The published Aada feature page groups information by guest, floor and office. Wayta exposes a menu experience alongside plan navigation. Tybl groups its offerings in the header, and Linear layers product detail beneath a restrained introduction. The new information architecture applies these principles to Serveza's own screens and content. No competitor assets were imported. Public source inspection covered the reference sites in the brief; the Tybl platform URL did not load through the web reader. Visual inspections and measurement coverage are reported separately from source inspection.

Local Chrome captured desktop and phone views at 1440 and 390 CSS pixels for Aada, Wayta, Tybl and Stripe. Aada keeps its role index with the introductory copy. Wayta moves the phone preview below the headline on mobile. Tybl gives photography and type separate areas, and Stripe preserves a prominent primary action as its narrative stacks. The design uses a comparable mobile reading order with Serveza's original product illustration and controls. Linear was accessible to the web reader, but its mobile screenshot timed out. The component libraries and supplementary examples received source-level review only.
