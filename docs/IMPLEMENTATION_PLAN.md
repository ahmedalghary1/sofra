# خطة التنفيذ والحالة

المرجع هو ملف المواصفات الأصلي في الجذر. التطبيق قابل للتجربة، لكنه لم يحقق جميع قصص المستخدم أو شروط الإطلاق التجاري. بوابات الاعتماد العملي في [RELEASE_READINESS.md](RELEASE_READINESS.md).

| المجال | الحالة | التفاصيل |
|---|---|---|
| الأساس والحسابات والعزل | جزئي | تسجيل ودخول واستعادة كلمة المرور، وتفعيل بريد المالك الجديد برابط صالح 24 ساعة لمرة واحدة مع إعادة إرسال محدودة؛ فروع وعضويات وأدوار وتعطيل الموظف واختبارات عزل. جولة إعداد للمالك والمدير من بيانات الفرع تشمل وصف المطعم والصنف والطاولة وموظف المطبخ وفتح شاشة المطبخ فعليًا؛ تحرير ملف المطعم وبيانات اتصال الفرع مع نشر اختياري في منيو الضيف. دعوات موظفين بالبريد، برمز صالح 7 أيام وقبول مرة واحدة وإلغاء وحد باقة وسجل تدقيق؛ يلزم إعداد SMTP واختبار التسليم الفعلي للتفعيل والدعوات والاستعادة قبل الإطلاق. العملة المعتمدة للإصدار الحالي هي الجنيه المصري؛ معاينة الملف التفاعلية مؤجلة. |
| الباقات | جزئي | تجربة 14 يومًا وحدود فروع وطاولات وأصناف وموظفين في خدمة مركزية، ومعاينة خفض الباقة للمالك عبر كل الفروع دون حذف بيانات، وتعليق المطعم بوضع قراءة فقط. تغيير الباقة يدوي من مشغل المنصة ويسري فور الحفظ. سجل تحصيل اشتراك يدوي بمرجع فريد وفترة ومبلغ بالجنيه المصري وهوية المشغل، مع عرض للمالك؛ لا يمدد الاشتراك تلقائيًا. فوترة آلية ومدفوعات إلكترونية وتجربة تزامن على PostgreSQL مؤجلة. |
| المنيو والطاولات | جزئي | تصنيفات مع إظهار/إخفاء، أصناف مع تعديل وتوفر، صور وأحجام بأسعار مستقلة، ومجموعات إضافات قابلة للتحرير مع حدود اختيار وخيارات أسعار وتوفر وترتيب وحذف آمن، وQR؛ استيراد CSV وXLSX بمعاينة واعتماد ذري وقواعد تحقق مشتركة. |
| طلب الضيف | منفذ للمسار الأساسي | سلة، تحقق خادمي، لقطة سعر، منع تكرار، متابعة حالة، ورمز جلسة طاولة يتغير عند إنهاء الخدمة دون تغيير QR. صفحة المتابعة تتيح طلبًا مستقلًا إضافيًا في الجلسة الحالية فقط. يعاد فحص حالة الطاولة والجلسة وحد الطلبات داخل معاملة الإنشاء بعد قفل الطاولة؛ اختبار التزامن الفعلي على PostgreSQL ما زال مطلوبًا. |
| شاشة المطبخ | جزئي | عرض وتحديث حالات وفحص اتصال واستعادة عبر polling كل 10 ثوانٍ، وتصفية حسب الحالة والطاولة والترتيب. حد تأخير قابل للضبط لكل فرع وعلامة تنبيه تتحول عند تجاوزه من وقت الخادم. محطات لكل فرع ضمن حد الباقة، وربط الصنف بمحطة مع حفظ توجيه سطر الطلب وحالات تحضير مستقلة لكل سطر مع سجل انتقالات، وتمنع جاهزية الطلب الموجّه قبل اكتمال جميع سطوره؛ الشاشة العامة تدير حالة الطلب كله وتظهر تنبيهًا للأصناف بلا محطة. الصوت وWebSocket واختبارات التزامن على PostgreSQL مؤجلة. |
| الخدمة والطلب التقليدي | جزئي | استدعاء الويتر والحساب وطلب موظف متعدد الأصناف والإضافات بنفس خدمة تسعير QR؛ إلغاء بسبب مسجل، وتعديل الطلب الجديد أو المستلم وغير المدفوع مع سجل نسخ قبل/بعد ومزامنة شاشة المطبخ. بعد بدء التحضير يمكن فتح طلب إضافي مستقل للطاولة من سجل طلباتها، مع فلتر للطاولة واختيارها مسبقًا ضمن الفرع والجلسة الحالية. سجل الطلبات مقسم إلى صفحات؛ استدعاءات الخدمة تعيد فحص الجلسة وحد التكرار بعد قفل الطاولة. تصحيح حالة الطلب خطوة واحدة للخلف للمالك أو المدير بسبب مسجل، للطلبات الجارية غير المدفوعة فقط. تعديل عناصر الطلب بعد بدء التحضير غير مسموح حتى لو صُححت الحالة للخلف. حدود استجابة منفصلة للويتر والحساب لكل فرع، مع تنبيه داخل شاشة الخدمة عند التأخير؛ إشعارات التصعيد الخارجية مؤجلة. |
| التقارير وإدارة المنصة | جزئي | أعداد وقيمة الطلبات والتحصيل اليدوي وأكثر الأصناف ومتوسطات التشغيل مع أعداد العينات، وزمن تحضير الأصناف حسب المحطة من سجل انتقالات السطور، ونطاق تاريخ يطبق على CSV. تصدير الطلبات يرسل الصفوف تدريجيًا ويحمي اسم الطاولة من صيغ الجداول؛ لوحة المشغل تنشئ مطعمًا بمالك وفرع أول وتجربة 14 يومًا، وتربط مالكًا موجودًا بمطعم آخر، وتضيف أو توقف فروعًا تحت حد الباقة مع سجل تدقيق وسبب لتغيير الحالة. المالك المنشأ من اللوحة يحصل على كلمة مرور مؤقتة يحددها المشغل ويشاركها معه؛ لا يُرسل بريد تلقائي في هذا المسار. إدارة الاشتراكات والتحصيل اليدوي متاحة، وتحرير الباقات داخل Django Admin يتطلب سببًا، والكيانات التشغيلية فيه للقراءة فقط. |
| عرض محلي تجريبي | منفذ للاستخدام المحلي | `demo_setup.py` يجهز مطعمًا وحسابات وأصنافًا وطاولات وطلبات تاريخية وشاشة مطبخ تبدأ فارغة؛ يعرض كلمات مرور عشوائية عند التشغيل، ويدعم إعادة التشغيل دون تكرار البيانات أو حذف الطلبات. يقتصر على `DEBUG=1` وترد خطوات الأجهزة المتعددة في [دليل العرض](DEMO_GUIDE.md). لا يمثل اعتمادًا للإنتاج. |
| صلابة الإنتاج | غير مكتمل | تحديد معدل الدخول واستعادة الحساب في قاعدة البيانات موجود، ومسار الصحة يفحص قاعدة البيانات ويرجع 503 عند تعذر الوصول إليها دون كشف التفاصيل. إعداد الإنتاج يرفض مفتاح المثال أو مفتاحًا قصيرًا والرجوع إلى SQLite دون رابط PostgreSQL. ما زالت مراقبة خارجية ونسخ احتياطي مجرّب واختبارات حمل ومراجعة أمنية وميدانية مطلوبة. |

## الخطوات التالية

1. اختبار تزامن حدود الباقات ومنع تكرار الطلبات على PostgreSQL تحت حمل حقيقي.
2. تجربة مسار الطلب الإضافي بعد بدء التحضير وتنسيق المحطات في مطعم فعلي.
3. إضافة قنوات تحديث لحظية عند تحديد استضافة مناسبة، مع إبقاء الاستعلام الدوري للاستعادة.
4. إضافة اختبارات واجهة للهاتف والتابلت والكمبيوتر واختبارات ضغط وعزل أوسع.
5. تشغيل تجربة مطعم فعلية ثم تثبيت التسعير والحدود وبيئة النشر.
