# بوابات اعتماد الإصدار

هذه القائمة للعمل عند توفر بيئة تجريبية منفصلة. نجاح اختبارات SQLite المحلية لا يعني اجتياز أي بند هنا.

## بيئة التشغيل

- [ ] توفير PostgreSQL واستضافة ودومين وHTTPS وتخزين دائم للصور والنسخ الاحتياطية.
- [ ] ضبط متغيرات `.env.example` في نظام الاستضافة دون حفظ أسرار في المستودع، ثم تشغيل `python manage.py check --deploy` ومعالجة التحذيرات المناسبة للدومين.
- [ ] تشغيل `python manage.py migrate --noinput` و`python manage.py collectstatic --noinput` في بيئة تجريبية، والتحقق من `/health/` وحالة 503 عند قطع قاعدة البيانات.
- [ ] ضبط SMTP وتجربة تسجيل مالك وتفعيل بريده، وإعادة الإرسال، واستعادة كلمة المرور، ودعوة موظف من بريد حقيقي.

## التزامن والبيانات

- [ ] اختبار إرسال الطلب نفسه بالتزامن بمفتاح واحد، ثم مفاتيح مختلفة للطاولة نفسها؛ لا يُحفظ الطلب المكرر ولا يُتجاوز حد الدقيقة.
- [ ] اختبار إنشاء طلب أو استدعاء بالتزامن مع إنهاء جلسة الطاولة أو تعطيلها، والتحقق من العزل بين المطاعم والفروع.
- [ ] اختبار حدود الباقة بالتزامن على PostgreSQL، خاصة إنشاء الطاولات والأصناف والموظفين والمحطات.
- [ ] نسخ PostgreSQL وملفات `media` إلى مكان مستقل، ثم استعادتهما في بيئة تجريبية ومقارنة عدد الطلبات ولقطات الأسعار وسجلات الحالة.

## التشغيل الميداني

- [ ] مراقبة أخطاء التطبيق وزمن الاستجابة وتوافر قاعدة البيانات مع تنبيه خارجي، وتجربة استجابة الفريق للتنبيه.
- [ ] اختبار RTL والتفاعلات على هاتف وتابلت وكمبيوتر فعليين، بما في ذلك المنيو والسلة والمطبخ والخدمة والتقارير.
- [ ] تجربة شبكة ضعيفة وقطع الاتصال وإعادة المحاولة، والتأكد من عدم عرض نجاح كاذب أو تكرار الطلب.
- [ ] تجربة مطعم خلال ساعات العمل، وتوثيق الطلبات المفقودة أو المكررة وأزمنة الخدمة وشكاوى الموظفين والضيوف.

## قرارات تجارية لاحقة

- [ ] تثبيت العملة والتسعير وحدود الباقات مع أصحاب المطاعم قبل تغيير الواجهات أو الفواتير.
- [ ] اختيار مزوّد دفع وفوترة إن أصبح الدفع الإلكتروني شرطًا للشراء؛ المسار الحالي يسجل التحصيل يدويًا فقط.
- [ ] مراجعة سياسة الخصوصية وشروط الخدمة والالتزامات الضريبية مع مختص قبل الإطلاق التجاري.
